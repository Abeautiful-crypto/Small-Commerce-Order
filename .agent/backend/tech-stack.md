# 技术栈约束（Tech Stack）

> 当涉及选型、落库、加缓存、接 DB/Redis、写迁移、调连接池时遵循本文件。
> 本题的核心难点是**状态一致性**（并发扣减、幂等、退款×发货互斥、迟到支付），
> 所以技术栈选型与用法必须服务于"每个时刻只有一种合法结果"，而不是为用而用。
> 后端语言相关的工程结构见 `backend/constraints.md`，本文件聚焦存储与缓存。

## 技术栈总表

| 组件 | 选型 | 职责 | 指定方 |
|---|---|---|---|
| 后端语言 | **Go 1.21+**（默认；若实际用 Java/Node 等，本文件 DB/缓存部分仍适用，仅语言相关片段调整） | 业务编排、接口、状态机 | 沿用既有假设 |
| 持久化存储 | **MySQL 8.0+**（用户指定） | 商品、订单、支付流水、退款单、发货记录、异常记录、用户/角色的**真相源** | **用户指定** |
| 缓存 | **Redis 7+**（用户指定） | 热点库存读加速、支付幂等短期去重、登录态、削峰锁 | **用户指定** |
| 前端 | 当前 `prototype/` HTML+JS 单文件；后续可落 React/Vue（见 `frontend/code-style.md`） | 拼多多风交互、角色权限拦截 | 沿用 |
| Schema 迁移 | `golang-migrate` / `sqlc` / `ent`（任选其一） | 版本化建表、加约束，禁止手改生产库 | 建议 |
| 连接池 | `database/sql` 连接池 + `go-redis` 连接池 | 复用连接、限流 | 建议 |

> 演示原型期（`prototype/` 单文件）仍可用内存态快速验证交互；**真实后端一律以 MySQL 为真相源、Redis 仅做缓存/去重**，不再用内存态当生产存储。

## 1. MySQL（持久化 · 真相源）

### 1.1 Schema 要点（与 `backend/constraints.md` 铁律对齐）
- **金额**：统一 `BIGINT`（单位"分"），**绝不**用 `FLOAT`/`DOUBLE`/`DECIMAL` 裸浮点。
- **可售数量**：`INT`（或 `BIGINT`）列；占用/释放一律
  `UPDATE 商品 SET 可售=可售-? WHERE id=? AND 可售>=?`，**以影响行数判定成败**，禁止"先 SELECT 再 UPDATE"。
- **幂等-支付**：支付流水表对 `渠道交易号` 建 **UNIQUE 索引**；重复通知只插流水（因唯一冲突失败），不动账。
- **幂等-状态**：状态列取值用枚举/CHECK；关闭/释放/收款走 **CAS**（`WHERE status='待付款' AND id=?`），失败即幂等命中。
- **流水只增不改**：收款/退款/发货/异常各自独立流水表，无 UPDATE/DELETE 历史行。
- **退款单来源字段**：`source` 列（`presale`/`late`），决定退款成功时是否恢复库存（仅 `presale` 恢复）。

### 1.2 事务与一致性
- 所有"跨多表且须一致"的操作（如下单占用商品库存 + 写订单 + 写占用流水）包在**一个事务**内，失败整体回滚。
- 强一致靠 **DB 约束 + 事务 + 行锁（SELECT … FOR UPDATE 或条件更新）**，不靠应用层内存锁"猜"。

### 1.3 禁止项
- 禁止用 Redis 计数代替 MySQL 库存（多实例下必不一致 → 超卖）。
- 禁止手改生产库 schema，必须走迁移脚本。
- 禁止在应用层缓存"当前可售数量"并据此扣减。

## 2. Redis（缓存 · 加速与去重，非真相源）

### 2.1 用途边界
| 用途 | 键设计 | 说明 |
|---|---|---|
| 热点库存读加速 | `stock:{商品id}` | 缓存可售数量，**只读**；写（扣/释）走 MySQL 事务，成功后再 `DEL` 该键 |
| 支付幂等短期去重 | `pay_dedup:{渠道交易号}` | `SETNX` + TTL（如 24h），与 MySQL 唯一索引双保险；命中即视为重复通知 |
| 登录态 / 角色 | `sess:{token}` | 存角色与用户标识，供接口越权校验 `order.Owner == currentUser` |
| 削峰锁（抢购） | `lock:buy:{商品id}` | `SET NX EX` 短时锁，**仅用于减少无效请求**，正确性仍由 MySQL 条件更新保证 |

### 2.2 缓存与 DB 一致性策略（Cache-Aside + 写失效）
- **读**：先查 Redis；未命中查 MySQL 并回写（带合理 TTL）。
- **写**：先更新 MySQL（事务提交成功），再 `DEL` Redis 对应键；**禁止"先更缓存再更 DB"**，禁止"用 Redis INCR 当库存真相"。
- **防穿透/雪崩**：热点 key 可加随机 TTL；不存在的库存查询用空值短缓存防穿透。

### 2.3 禁止项
- 禁止用 Redis 库存值作为扣减依据（真相只在 MySQL）。
- 禁止 Redis 锁作为"不超卖"的唯一保证（仅削峰）。
- 禁止把幂等去重只放 Redis（Redis 丢数据会失守）→ 必须 MySQL 唯一索引兜底。

## 3. 后端语言与框架（默认 Go）
- 工程结构见 `backend/constraints.md` 第 1 节（`cmd/ internal/{domain,store,service,api} pkg/`）。
- 数据库访问集中在 `internal/store`，ORM/原生 SQL 任选，但**所有原子更新与唯一约束都落在 SQL 层**。
- 接入 MySQL 用 `database/sql` + `go-sql-driver/mysql`；接入 Redis 用 `go-redis/v9`。

## 4. 连接池与迁移
- MySQL 连接池：`sql.DB.SetMaxOpenConns` / `SetMaxIdleConns` 按压测调；超时关闭类长事务避免占满连接。
- Redis 连接池：`go-redis` 的 `PoolSize` 合理配置，设置读写超时。
- 迁移：每次 schema 变更写迁移文件（up/down），提交前执行，保证环境一致。

## 5. 技术栈相关禁止项速查
1. 库存真相只在 MySQL，Redis 只缓存读、不计数。
2. 幂等必须 MySQL 唯一索引兜底，Redis 去重只是辅助。
3. 金额永远 BIGINT 分，不用浮点类型。
4. 跨表一致走事务 + 行锁/条件更新，不靠内存锁。
5. 不引入 MQ/分布式事务等重组件除非确实必要（超时关闭优先定时扫描 DB）。
