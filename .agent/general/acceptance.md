# 06 · 验收标准

> 每次完成功能自测、提交前遵循本文件。通用原则见 `general/principles.md`，后端铁律见 `backend/constraints.md`。

## 1. 通用门槛（每次提交前必过）

- [ ] 构建通过（`go build ./...`；前端 `build` 通过）
- [ ] `gofmt`/`go vet` 无输出（前端 lint 无错）
- [ ] 改动涉及的核心不变量有单测覆盖（不超卖、幂等、退款×发货互斥、越权）
- [ ] 相关单测通过（`go test ./...`）

## 2. 五大场景验收清单（来自需求文档第五节，逐场景给断言）

每个场景的"通过"= 数据库最终态 + 库存 + 流水三项同时成立。

| 场景 | 操作步骤 | 验收断言（必须全部满足） |
|---|---|---|
| **1 正常成交** | 上架→下单→支付通知→发货→查询→对账 | 订单 `已发货`；可售 −1 且不再变化；收款流水 +1（金额=单价×数量）；净额=收款；异常流水 0 |
| **2 缺货与弃单** | 20 并发抢 5 件；对未付单取消/超时 | 成功占用数=5，第 6 起报"可售不足"；关闭后可售加回且**只加一次**（重复关闭幂等）；他人可购回 |
| **3 售前退款** | 申请退款→渠道失败→重试成功 | 退款中期间发货被挡；首次失败保留待处理；重试成功后 `已退款` 且**可售恢复 +1**；退款流水 2 条（失败+成功） |
| **4 迟到支付** | 超时关闭→收到成功通知→进异常→退款 | 订单**不复活**（仍为已关闭）；异常支付列表可见；退款成功后**无重复收款、无重复退款、库存不多不少（关闭时已释放，本次不恢复）** |
| **5 操作异常** | 并发退款+发货；重复通知；越权访问 | 退款与发货只出一种结果；重复通知只收一次款；越权访问明确 403（前端 `requireRole` 拦截 + 后端校验） |

## 3. 自动化验收

- 提供**验收 Skill / 测试脚本**，一键跑完上述 5 个场景并输出 PASS/FAIL 与每场景断言明细。
- 任何一次"完成功能"后，先跑相关场景断言，再提交。
