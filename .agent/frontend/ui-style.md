# 04 · 前端 UI 与样式规范（拼多多风格）

> 视觉与交互层约束。原型以拼多多为参考：橙红主题、移动端优先、强商品感。代码层见 `frontend/code-style.md`，权限见 `frontend/permission.md`。

## 1. 设计语言（拼多多风）

- 主色：橙红渐变（`#FF4D4F` → `#FF7A00` 区间），辅助色白底深字；促销红 `#E02E24` 用于价格与按钮。
- 圆角 8–12px；卡片化布局；轻投影；留白克制，信息密度偏高（电商感）。
- 价格永远大红、带 `¥`、划线原价置灰；"已拼 X 件 / 已售罄"等标签用胶囊样式。

## 2. 移动端优先（响应式）

- 以 375px 设计稿为基准，原型用手机框包裹；断点：≤480 单列，≥768 可双列。
- 触控目标 ≥ 44px；底部固定操作栏（如"发起拼单 / 单独购买""越权演示"）。

## 3. 组件化

- 复用组件：商品卡（图+标题+价格+按钮）、角色卡片、订单行、操作按钮组、Toast、确认弹窗、空状态。
- 组件只接收 props / 状态，不越权发起写操作（写操作走 `api/` + `requireRole`，见 `frontend/permission.md`）。

## 4. 用户反馈（强制）

- 每次操作（下单/支付/取消/退款/发货）**必须有明确反馈**：成功 toast、失败明确原因（如"可售不足""越权：未做任何改动"）。
- 危险操作（取消、退款、关闭）弹确认；幂等按钮在请求进行中禁用，防重复点击。
- 加载态用骨架屏或局部 loading，不整页白屏。

## 5. 状态可视化

- 订单状态用色彩徽章（待付款灰、待发货蓝、退款中橙、已退款绿、已关闭灰、异常红），与需求文档状态机一致。
- 关键流转（占用/释放/出库）可在运营页用滚动日志呈现，便于演示"每个时刻只有一种合法结果"。

## 6. 禁止项

- 禁止无反馈的静默失败；禁止把错误吞进 `catch` 不提示。
- 禁止为"好看"牺牲可读性（如红底红字）；遵循对比度。
- 禁止在不同页面各写一套主题色；统一走 `styles/` 设计变量。
