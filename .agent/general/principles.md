# 01 · 总体原则与 AI 行为准则

> 本文件是不分前后端的"宪法总纲"。任何一次写代码、加测试、提交代码，都必须先读并遵循本文件，再进入 `backend/constraints.md`/`frontend/code-style.md` 等专项约束。

## 1. 总体原则

1. **状态机是唯一裁判**：任何订单状态变更，必须能映射到需求文档第四节的状态迁移表；找不到对应迁移的改动一律禁止。
2. **闭环优先**：一个功能点 = 写代码 → 立即自测 → 沉淀问题（若有）→ 提交。禁止"写完一堆再测"。
3. **整数与原子**：金额永远 `int64` 分；库存占用永远原子条件更新，禁止"先查后扣"。（后端实现见 `backend/constraints.md`，前端展示换算见 `frontend/code-style.md`。）
4. **不擅自扩大范围**：题目明确不在范围的事（购物车、多商户、真实物流、部分退款、签收/退货）一律不做。只交付需求文档要求的三类产物（原型页 / 业务 Skill / 验收 Skill）。
5. **不静默吞错**：遇到未预期行为、校验失败、并发冲突，必须显式报错并沉淀到 `general/issue-log.md`，禁止伪造"测试通过"。
6. **先读后动**：动手前先确认本次改动对应的状态机迁移与库存占用语义；不确定就回到需求文档，不拍脑袋。

## 2. AI 行为准则（开发流程）

1. **增量开发**：一次只做一个功能点（如下单占用、支付通知幂等、退款），不一次性铺开。
2. **完成即测**：每个功能点写完，**立刻**用单测 / 接口调用 / 原型点击验证该点，通过后才进入下一个。
3. **先失败后通过（TDD 倾向）**：复杂不变量（不超卖、互斥）先写断言再写实现。
4. **提交前自检**：`general/acceptance.md` 的通用门槛全过 + 相关场景断言通过。
5. **不伪造结果**：测试没过就不说过了；并发竞态没稳定复现就标注"待复现"，不谎称已修。
6. **范围守护**：发现需求外的"顺手优化"念头，先停下，问用户是否要做，不自行加。

## 3. 问题沉淀机制（重要 · AI 自主学习成长）

> **目的**：本机制不只是"记 bug"，而是让 AI 把每次踩坑转化为**可跨会话复用的经验**——下次遇到同类问题先检索 `general/issue-log.md` 直接套用根因与解法，实现**自主学习成长**，避免重复踩坑（详见该文件头部的"自主学习库"定位）。
> **规则**：开发中遇到的任何 bug、竞态、设计冲突、需求歧义，**先写入 `general/issue-log.md`（与本目录同处） 再动手修**；修完后回填"解决方式"与"是否上升为约束"。

### 3.1 文件位置与格式

- 路径：`general/issue-log.md`（与本文件同目录）
- 每条问题一个二级标题，含以下字段：

```markdown
### [YYYY-MM-DD] 问题简述（如：并发退款与发货双成功）
- 现象：
- 复现步骤：
- 根因：
- 解决：
- 是否上升为约束：是 / 否（若"是"，摘一句补进 `backend/constraints.md` 第 2 节铁律，或 `frontend/code-style.md`/`frontend/permission.md` 的前端约束）
- 关联需求：需求文档第 X 节 / 状态机迁移 Y
```

### 3.2 与约束的闭环

- 沉淀的问题若暴露了规则漏洞，修复后**同步更新对应专项约束文件**（后端铁律进 `backend/constraints.md`、前端规则进 `frontend/code-style.md`/`frontend/permission.md`），让规则自我进化。
- 已识别的预防性坑（来自需求分析第六节）已预置在 `general/issue-log.md` 顶部，开发时对照规避。

## 4. 交付物对照（呼应需求文档第八节）

| 交付物 | 说明 | 本合集如何保障 |
|---|---|---|
| 原型页 | 商品/订单、仓库待发货、客服退款与异常、运营核查 | `general/acceptance.md` 场景可在原型点击验证 |
| 业务 Skill | 查跨环节约束（库存/退款/发货一致性） | `backend/constraints.md` 铁律为 Skill 提供判定依据 |
| 验收 Skill | 跑完 5 个场景 | `general/acceptance.md` 自动化验收 |
