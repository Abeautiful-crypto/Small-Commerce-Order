# 07 · Git 提交规范（引自 `commit-convention.md`）

> 每次提交前遵循本文件。格式与类型定义引自用户提供的 `commit-convention.md`（飞书 meegle 体系）。

## 1. 格式

```
[类型] [版本号] [需求/Bug编号] 描述
```

## 2. 类型

| 类型 | 用途 |
|------|------|
| feat | 新增功能需求 |
| fix | 修复 Bug |
| hotfix | 线上紧急修复（事后补编号） |
| opt | 优化（性能、代码质量、重构） |
| docs | 文档变更 |
| test | 测试相关 |

## 3. 必填规则

| 类型 | 版本号 | 编号 | 说明 |
|------|--------|------|------|
| feat | 必填 | 必填 | 新功能必须关联需求编号 |
| fix | 必填 | 必填 | Bug 修复必须关联编号 |
| hotfix | 必填 | 可选 | 紧急修复，编号可事后补 |
| opt | 必填 | 可选 | 优化可不关联编号 |
| docs | 可选 | 可选 | 文档变更可都不带 |
| test | 可选 | 可选 | 测试相关可都不带 |

## 4. 示例

- `[feat] [v1.0.0] [#1001] 新增下单占用库存接口`
- `[fix] [v1.0.0] [#1002] 修复重复支付通知二次收款`
- `[opt] [v1.0.0] 重构支付回调状态机守卫`
- `[docs] 更新 AI 开发约束规则`
- `[test] [v1.0.0] 补充不超卖并发测试`

## 5. 通用规则

- 描述用**中文**，简洁明了。
- 版本号：`v{主}.{次}.{修订}`，如 `v1.0.0`。
- 编号规则：**若已接入飞书 meegle**，则为工作项 ID（`#数字`），且 feat/fix 提交时执行 `meegle workitem get --work-item-id {编号} --project-key r17te9` 校验真实性；**若本项目未接入 meegle**（演示/作业场景），编号改为需求文档章节号或留空，并在提交说明里注明"未接入 meegle"。
- 一次 commit 只含**一个类型**；混合变更拆多次提交。
- 禁止用 AI 自动编造不存在的编号。
