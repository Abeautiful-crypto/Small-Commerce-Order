# 02 · 后端约束（Go）

> 当写后端代码、加接口、改状态机、处理库存/支付/退款时遵循本文件。前端相关见 `frontend/code-style.md`/`frontend/ui-style.md`/`frontend/permission.md`，通用原则见 `general/principles.md`。

## 0. 前提假设

| 项 | 假设 |
|---|---|
| 后端语言 | **Go 1.21+** |
| 存储 | **MySQL 8.0+**（持久化，用户指定）+ **Redis 7+**（缓存，用户指定）；演示原型期可用内存态，真实后端以 MySQL 为真相源、Redis 仅加速/去重。详见 `backend/tech-stack.md` |
| 金额单位 | **整数"分"（`int64`）**，全程禁止浮点 |
| 需求锚点 | `订单交易系统需求分析.docx` + 状态机 + 8 条业务规则 |

## 1. 工程结构

```
cmd/                 # 入口（main）
internal/
  domain/            # 订单/商品/退款/发货/异常 的领域模型与状态机
  store/             # 数据访问（原子更新、唯一约束）
  service/           # 业务编排（下单、支付通知、退款、发货）
  api/               # HTTP 接口 + 越权校验
pkg/                 # 可复用工具（如 money、idgen）
```

- 包名全小写、单数；文件驼峰；一个文件一个职责。
- 领域层不依赖存储层（依赖倒置），状态机逻辑集中在 `domain` 内一处，禁止散落 `if status ==`。

## 2. 关键编码铁律（本题专属，违反即打回）

| 铁律 | 要求 | 反例（禁止） |
|---|---|---|
| 金额 | 一律 `int64`（单位分），禁止 `float`/`double` | `price float64` |
| 库存占用 | 原子条件更新：`UPDATE 商品 SET 可售=可售-? WHERE id=? AND 可售>=?`；返回影响行数判断成败 | 先 `SELECT` 再 `UPDATE` |
| 幂等-支付 | 渠道交易号建**唯一索引**；重复通知只记流水、不动账 | 同交易号二次收款 |
| 幂等-关闭/释放 | 关闭/释放/收款用**条件状态更新**（CAS：`WHERE status='待付款' AND id=?`），失败即幂等命中 | 无条件 `UPDATE status` |
| 状态机 | 所有迁移经统一 `Transition(from,to)` 守卫，非法迁移返回明确错误 | 业务代码里直接 `order.Status = "已发货"` |
| 退款恢复库存 | 按**退款单来源**（售前/迟到）决定恢复与否；迟到支付退款**不恢复**（关闭时已释放过） | 用订单当前状态 `if` 猜是否恢复 |
| 退款×发货互斥 | 谁先 CAS 成功谁赢，输方收明确失败；已发货禁止受理售前退款 | 两边都成功 |
| 越权校验（接口层） | 买家接口强制 `order.Owner == currentUser`，否则 403 | 仅靠前端隐藏按钮 |
| 流水不可变 | 收款/退款/发货/异常均落**只增不改**的流水表 | 改历史流水"抹掉"异常 |
| 模拟渠道回调 | 渠道退款结果等回调接口必须校验**真实请求身份**或渠道签名；演示态至少限制为客服/运营 | API 层内部构造 `channelActor()` 绕过鉴权，任何角色可确认退款成功 |
| 时间 | 超时判断用**服务端时间**，不信任客户端 | 客户端传 `expireAt` |

> 前端的"金额展示换算"与"越权渲染拦截"规则见 `frontend/code-style.md`/`frontend/permission.md`，后端这里是数据与接口的真相源。

## 3. 命名 / 注释 / 日志

- 变量/函数见名知义；状态值用常量（`StatusPendingPay` 等），禁止魔法字符串。
- 公共函数写 Go doc；状态机迁移处必须注释"对应需求文档第几条规则"。
- 日志结构化（key=value），关键动作打印：动作、订单号、前后状态、库存前后值、渠道交易号。

## 4. 并发

- 正确性靠**数据库约束 + 事务**保证，不靠应用层内存锁"猜"。
- 演示并发（如 20 人抢 5 件）用 goroutine + `sync.WaitGroup` 起压，断言最终不超卖。
- 所有共享状态访问走 `store`，不得绕开。

## 5. 静态检查（提交前必过）

- `gofmt` / `go vet` / `golangci-lint` 零告警。
- 编译通过、单测通过（见 `general/acceptance.md`）。

## 6. 后端一页速查

1. 这次改动对应状态机哪条迁移？——没有就不做。
2. 金额 `int64` 分？库存原子条件更新？——不是就打回。
3. 幂等靠唯一索引 / CAS？退款恢复看"来源"？——不是就可能重复收/重复释放。
4. 状态机经 `Transition` 守卫？流水只增不改？——直接改状态/流水即违规。
