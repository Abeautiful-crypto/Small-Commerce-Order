# 05 · 前端权限与越权守卫规范

> 角色权限是本项目的硬约束（买家/运营/仓库/客服）。本文件规定前端如何落地"权限不能越权"，并与后端接口越权校验（`backend/constraints.md` 铁律）双保险。

## 1. 角色与界面映射

| 角色 | 可见界面 | 可发起的操作 |
|---|---|---|
| 买家 | 商品浏览 / 我的订单 | 下单、支付、取消、超时、申请退款（仅自己订单） |
| 运营 | 商品管理 / 对账核查 | 上/下架、库存核查、汇总（只读流水） |
| 仓库 | 待发货清单 | 一次发货登记（仅待发货单） |
| 客服 | 退款审核 / 异常支付 | 同意/拒绝退款、处理迟到支付退款 |

> 题目未设独立"卖家"角色；运营一侧即商户侧（管商品与库存）。如需独立卖家角色，先与用户确认再加。

## 2. requireRole 守卫（强制）

- 每个写操作函数第一行：`requireRole(currentRole, allowedRoles, action)`，不通过直接抛/返回 `⛔ 无权访问`，**且声明"未做任何数据改动"**。
- 守卫失败**不回滚任何状态**（因为本就没改），但要在日志/提示里明确"本次操作被拦截"。
- 后端同样校验（见 `backend/constraints.md` 越权铁律），前端守卫是体验层，不能替代后端。

## 3. 数据隔离

- 买家只能读取/操作 `order.owner == currentUser` 的订单；过滤在 api/store 层完成。
- 角色切换（重新登录）必须清空上一角色的本地状态，避免串数据。

## 4. 越权演示（验收硬证据）

- 页面固定提供"越权演示"入口：用当前身份点别的角色按钮（如买家点"商品上架""登记发货"），应弹出明确拦截提示。
- 该演示用于验收场景 5（操作异常）的"越权访问被明确拒绝"断言。

## 5. 禁止项

- 禁止仅靠"前端不显示按钮"来实现权限（后端必须校验）。
- 禁止把一个角色的写操作接口暴露给其他角色的调用方而不校验。
- 禁止角色切换后残留上一角色数据。
