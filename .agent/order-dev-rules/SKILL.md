# 订单交易系统 AI 开发约束规则（加载入口）

本 Skill 封装本项目的 AI 辅助开发约束。**任何一次写代码 / 加测试 / 提交前，先读 `.agent` 根目录的 `README.md`（总索引），再按本次改动类型跳到对应文件夹下的文件。**

约束已按"通用 / 后端 / 前端"分文件夹存放，按需加载：

1. **`general/principles.md`** —— 总纲：状态机是唯一裁判、闭环优先、问题沉淀机制、AI 行为准则。**每次任务开始前都过一遍。**
2. **`backend/constraints.md`** —— Go 工程结构、关键编码铁律（金额 `int64` 分禁浮点；库存原子条件更新禁先查后扣；支付/关闭幂等靠唯一索引 + CAS；状态机集中守卫；退款恢复看"来源"售前恢复/迟到不恢复；退款×发货互斥；买家接口越权校验；流水只增不改）、并发、静态检查。
3. **`frontend/code-style.md`** —— 前端目录/命名/状态单一来源/金额展示换算/防越权渲染/禁止项。
4. **`frontend/ui-style.md`** —— 拼多多视觉风格、移动端优先、组件化、用户反馈、状态可视化。
5. **`frontend/permission.md`** —— requireRole 守卫、数据隔离、越权演示（角色：买家/运营/仓库/客服）。
6. **`general/acceptance.md`** —— 通用门槛 + 五大场景断言清单（正常成交 / 缺货弃单 / 售前退款 / 迟到支付 / 操作异常）+ 自动化验收 Skill。
7. **`general/git-convention.md`** —— `[类型] [版本号] [编号] 描述`（feat/fix/hotfix/opt/docs/test），引自 `commit-convention.md`；未接入 meegle 时编号改需求文档章节号或留空。

配套文件：**`general/issue-log.md`**（与本目录同处）—— 任何 bug/竞态/歧义先写再修，顶部预置 P1–P7 预防性坑。

## 执行纪律（每次开发任务开始前）

1. 读 `README.md` → 确认本次改动类型（后端/前端/通用），加载对应文件夹下的文件。
2. 确认本次改动对应的**状态机迁移**与**库存占用语义**（没有合法迁移就不做）。
3. 写代码 → **立即自测本功能**（对照 `general/acceptance.md` 相关场景断言）→ 通过再继续。
4. 遇到未预期行为：先追加到 `general/issue-log.md`，再修复，最后回填"是否上升为约束"。
5. 提交前过 `general/acceptance.md` 通用门槛；feat/fix 按 `general/git-convention.md` 格式带类型/版本号/编号。

> 需求锚点：`订单交易系统需求分析.docx` 与状态机；原型：`prototype/拼多多风格原型.html`。
> 题目明确：**必须执行第一部分全部要求，不能只交付通知接口**。
